# 实验协议与验收

## 任务与样本

- 固定完整 workload manifest：输入 ID、顺序、文件 SHA256、必要的尺寸/预处理信息。校验 HAP 内的输入和模型；记录构建日志、提交、补丁、HAP SHA256、工具/系统版本。
- 正常产品处理链优先于模拟点击。已有终端 runner 时复用；不要为测量改变模型、返回结果或业务完成标准。
- 冷启动整批与逐图冷启动是不同工作负载。明确首次模型加载是否计入；以第一张业务 BEGIN 至本批最终完成标记为整批窗口，包含图片切换和失败处理。它不必包含进程启动至第一条 BEGIN 之前的耗费，不要声称包括该段。
- 跑完 N 次尝试不等于 N 次成功。保存每张终止类型、输出完整性、耗时和必要质量指标；不要删除慢样本/失败样本来改善平均值。若另给成功子集比较，明确分母和排除规则。

## 环境与重复

- 记录设备温度、SoC、电压、屏幕亮度/自适应状态、网络和后台条件。需要稳定亮度时保存原值再设定，结束恢复；亮度未固定则作为限制记录。
- 首先定义冷/热缓存条件，不暗中预热。重复试验之间尽量回到相似温度和电量区间；不能做到时报告温度范围及次序。
- 预先安排至少两轮完整功耗作为初步重复性检查。ABBA 或交替顺序可减小顺序偏差，但不等于已经消除混杂因素。根据波动、温度和所需可信度决定是否增加重复；不要自动无限重跑。
- 用独立内存轮隔离 profiler 开销。单次高覆盖内存轮可给观察值，不把它称为重复试验稳定峰值。
- 比较行为/质量：输出 token 数、输入档位、失败次数不同，电量差不等于某一个算子或 NPU 优化效果。

## 采集控制

- 同一设备串行。每轮使用唯一 run ID、输出目录与远端临时目录；不清系统 HiLog。
- 安装后才进入测量准备。明确验证了安装的具体 HAP；本地哈希 + skip-install 本身不能证明已安装版本。
- 先采集低负载空闲基线，再启动业务，完成后继续采后基线。初次可用前后各 7–15 秒的有效平稳段；短段是折中，不是准确性保证。波动大时延长或用匹配的独立空闲对照。
- 留出基线、完整业务、后采集余量；runner 超时不得超过采集可覆盖时长。耗时未知时采用业务完成后的有界停止，并验证 trace 正常落盘；不要靠强杀产生截断 trace。
- 设备采样必须有界且不能脱管；恢复约束见 [托管测量](omh-measurement.md)。正常恢复和证据回收在 job 退出前完成；不声称 finally 能覆盖取消、超时或断连。未验证异常恢复的供电改动不得执行。
- 每次设备调用必须使用 omh，遵循单命令时限，保存 stdout/stderr 和退出码；核对远端成功文本。能用参数数组就不用复杂嵌套 shell 字符串。

## 验收门槛

同时满足：

1. HAP/输入/模型来源清晰，真实部署成功。
2. 本轮唯一标记存在；索引连续且数量等于 manifest，结果未串入历史日志；PID 非空且目标 Ability 前台。
3. 时钟同源或偏移已校准；任务起止被采样覆盖，基线同样有覆盖；无跨长缺口积分。
4. 禁 USB 输入轮中，实际输入为零且电池确实放电；模式/节点读回正确。
5. trace 可完整解析，重复包去重；XPower 所比较窗口 valid 且 coverage=100%，否则该方法标不可用。不能让次要模型缺测抹掉其他有效方法，但不能把部分窗口值报为完整窗口值。
6. 供电/屏幕设置已恢复且有回读证据。

基础设施失败：保留证据，定位后修复重试；业务错误：保留成本并单列失败。若系统日志提示丢弃，不宣称全系统日志无丢失；仍需单独确认业务协议与原始测量完整。

## 汇总与报告模板

| 指标 | 定义 | 必须附带 |
|---|---|---|
| 总耗电 mAh | 每批增量电荷，多轮均值 | 单轮值/范围、基线、成功分母 |
| 峰值电流 mA | 窗口内最大采样电流，按声明扣基线 | 实际采样间隔、采样下界性质 |
| 平均电流 mA | 多轮总增量电荷 × 3600 / 总时长 | 不混用等权均值和时间加权均值 |
| 峰值内存 MB/MiB | 同口径完整任务内最大有效样本 | Total/PSS/RSS 口径、DMA覆盖 |
| 平均内存 MB/MiB | 有效覆盖区间内时间积分 / 覆盖时长 | 覆盖率、启动缺口、最大缺口 |

同时给出整机原始电荷与扣基线估计，避免隐藏归因假设。记录每种方法底层数据源；说明没有独立校准时无法断言“最准”。给出方法选择、证据路径/指纹、复现步骤、版本与恢复结果。不要把旧报告的历史指标当当前结果。
