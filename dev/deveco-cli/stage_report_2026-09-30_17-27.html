实现与使用

omh deveco auth status
omh deveco auth login
# 在应用根目录；先通过 omh acquire 取得目标设备租约
omh deveco signature generate --lease TOKEN --product default --timeout 10m

签名任务经现有调度器托管，设备枚举只返回租约设备；UDID 和设备类型查询通过 omh。签名结束后等待清理释放，再重新申请安装租约。打印的任务 ID 支持 status/cancel。

开发 skill 检测当前 product 的签名配置及材料；缺失时尝试自动签名。未登录时，Codex 输出登录事件并由 agent 使用侧栏浏览器打开原始 URL；非 Codex 调用系统默认浏览器。账号认证等待用户完成，不代填密码。

复用官方证书、登录和云端逻辑，Profile 可以包含账号已有其他设备。默认不强制重新生成材料。签名失败与设备回收失败分开判定。

复现与边界

源工程来自官方 CLI 1.2.1 内置 application 模板，临时目录 /tmp/omh-deveco-smoke-20260930。可用 devecocli create --app-name OmhSigningSmoke --bundle-name com.omh.signing.smoke --api-level 22 --project-path NEW_DIR 创建新工程。准备兼容的 DevEco SDK、Node、官方 CLI、华为开发者登录和可用真机；按上述认证和 omh 签名流程执行，安装工程 ohpm 依赖，用 Hvigor assembleHap 构建，然后重新申请设备并经 omh install / aa start 验证。签名材料由登录账户新生成，不能从报告复用秘密。

Windows/Linux 的真实 SDK、浏览器登录与签名没有在本机验证；CI 已加入 Node 并保留四平台原生测试矩阵，未宣称远端 CI 已运行。默认系统浏览器路径做了替身验证，没有额外打开真实系统浏览器登录。

所有结果是本次时间点的记录。临时证据在 /tmp，可能被系统清理；官方生成的材料仍在官方管理目录，未写入仓库。hook 与进程适配属于合作性防护，不是操作系统沙箱。
