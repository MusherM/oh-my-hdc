# omh 托管测量

## 执行边界

先构建并验收 HAP，再由唯一测试所有者申请租约，声明所有被测包。设备发现用 omh devices；安装、shell 探测、采样和 file send/recv 用 omh exec；HiLog 用 omh logs。不允许已有 runner 内部直接运行 SDK hdc 或另一个连接器。

长测用 omh job start 启动真实 runner。将部署验收、前基线、业务、后基线、恢复及回读、证据回收纳入同一个有限任务；预算为恢复留出余量，并在调度器硬超时之前主动结束实验。job 退出立即释放，不能事后继续使用原凭证取 trace。离线分析不占手机。分轮使用不同 job 时必须重新申请并核验同一目标与条件，不自动换设备后混算结果。

runner 使用调度器提供的 OMH_BIN、OMH_LEASE；参数按数组传递，例：`"$OMH_BIN" exec --lease "$OMH_LEASE" -- shell ...`。需要的应用路径和输入通过明确参数传递，不假设提交终端的环境变量会被继承。

每条 exec 最多 10 分钟；托管 job 不取消这一限制。不用无限日志、空轮询或心跳冒充工作负载。采样器必须有界、保持受管理的生命周期；不 nohup、不 daemonize、不启动脱离管理的设备任务。无法在此约束下运行的现有采集器先适配，不能仅在外层包一个 job 就宣称兼容。采样调用与业务观察的开销要纳入干扰检查。

## 恢复能力门槛

omh 释放清理停止声明的应用及所属主机进程/转发，但不恢复供电、亮度或其他系统设置，也不保证主机 finally 会在取消或硬超时时完成。设备显示 free 不是设置已恢复的证明；recover 也不验证实验设置。

修改设置前须有针对当前设备及采集器的正常、取消、超时、断连恢复证据。特别是 HIZ/充电开关：仅有 trap、主机 finally 或脱管 watchdog 不满足门槛。当前 skill 不提供通用的异常恢复执行器；没有证据时禁用此实验路径，保留可用的只读测量，或选用适配的外部仪器，并说明功耗解释边界。

不能在持有租约期间拔 USB 后改用原生无线 HDC。无线或其他供电路径必须在试验前完成调度兼容核验，保留相同设备身份且保持在线；断连会使旧租约失效。

## 验收与失败

先验证真实业务、完整采样和恢复回读，再检查 job result、reason、lease_state 与 cleanup_error。退出 0 不代表业务通过，也不代表设备恢复。取消/超时后仅检查已有证据和 omh 状态，不复用旧 token 或自动重跑。已失效时若需要诊断设备，按调度恢复流程处理并重新申请；设置恢复失败必须单独报告，不以调度清理成功覆盖。
