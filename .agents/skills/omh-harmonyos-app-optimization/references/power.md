# 功耗方法与统计

## 三类读数分开报告

| 路径 | 可回答什么 | 主要限制 |
|---|---|---|
| 电量计累计值差分 | 电池实际净电荷变化 | 缩放/方向、量化、更新频率，供电混杂 |
| sysfs / BatteryService / SmartPerf 电流积分 | 采样电池电流及窗口电荷 | 可能同源；采样丢峰和传感器更新滞后 |
| XPower RealBattery / AppStatistic | 电池序列；系统模型的应用分项归因 | 两者口径不同；时间桶、版本和分项覆盖 |

可用外部校准仪器时补充验证，但先解释接线边界：USB 端仪表读到的可能包含充电与转换损耗，不能自动视为应用或电池能耗。只看电量百分比通常分辨率不足以比较短批次。

## 单位、正负、累计值

1. 同时记录 `current_now`、`voltage_now`、可用的 `charge_counter`、温度、SoC、输入电流及供电模式。
2. 核对每个节点的单位；某些华为设备电流为 mA，而电压为 µV，不能套用其他 Linux/Android 设备的单位。
3. 用明确放电与充电状态核对符号。统一分析中的“放电为正”，保留原始值。
4. 累计节点可能表示剩余电荷、累计消耗或其他量；实测方向与更新规律。某设备的“放电时递增、差分除以 1000 得 mAh”只属于该设备适配，不能全局硬编码。
5. 对计数跳变、回绕、重置、量化与采样断档作检查；不能通过调缩放系数强行使两种读数一致。

## 计算

用秒作为时间、mA 作为电流：

- `Q_device(mAh) = integral(I_discharge(t) dt) / 3600`。
- 已确认单位和方向的累计电量计：`Q_gauge = signed_delta(counter) × scale_to_mAh`。
- `I_idle` 来自前后平稳基线，可用两段均值的平均；预先说明段长、与任务的间隔和加权方式。
- `Q_increment = Q_device − I_idle × T / 3600`。
- `I_average_increment = Q_increment × 3600 / T`。
- `I_peak_increment_estimate = max(sampled_I_discharge) − I_idle`。
- 能量若需 mWh：`integral(V_volts(t) × I_mA(t) dt) / 3600`；不要把 mAh 写成功率。

对不等间隔采样使用梯形积分并裁剪起止边界。只有相邻、有效且间隔可接受的样本才能插值；不外推到未覆盖启动阶段。保留最大采样间隔及有效覆盖率。

各方法独立算自己的基线，避免拿一个传感器的基线扣另一种模型。分别用前、后基线计算敏感性范围；这是基线敏感性，不是置信区间。增量为负可能表示混杂或分辨率不足，不能静默截断为零。

## XPower

- 分清 RealBattery 的整机电池序列与 AppStatistic 的应用模型估算，不能把二者当两份独立应用计量。
- 读取当前插件 schema 和解析实现。历史上见过 `xpower-plugin`、`REAL_BATTERY`、`APP_STATISTIC`、`APP_DETAIL` 与约 3 秒时间桶；不要假定所有系统相同。
- 原始电荷单位核对后再转换；已见 mA·s → mAh 需除以 3600。保留证据出处，不凭字段名猜测。
- RealBattery 序列可能带负数符号扩展、packed varint 与重复包；按实际 schema 解码、校验包边界、去重。时间桶内均匀分配时间戳属于重建假设；名义 100 ms 不代表传感器独立更新 100 ms。
- 时间桶只覆盖部分任务时，可按重叠比例估算并给边界上下界；检查完整任务覆盖。桶均值的最大值不是瞬时电流峰值。
- 明确是否含显示屏；展示 CPU/GPU/屏幕等分项后再给合计。没有独立 NPU/DDR 项不证明完全漏计，但无法确认时不能称其为完整 NPU 能耗。

## 归因和方法选择

电池测量覆盖整机电池供电负载，因此任务造成的 NPU 活动包含在其中；扣基线后仍可能混入后台任务、显示内容和温度变化。这是“任务增量估计”，不是精准隔离的应用或 NPU 电量。

优先比较电量计差分与低干扰电流积分是否一致，再用应用模型解释组成。SmartPerf、BatteryService、sysfs、RealBattery 可能复用同一硬件数据源；两票接近不能构成独立多数表决。差异大时先查单位/符号、USB 输入、时间窗口、更新频率、基线和工具开销，而不是直接选择较小数值。
